# Sources

Every candidate source for prices, one row per site and market. Only official brand sites and authorized dealers (see `../docs/PRODUCT.md`).

Survey run 2026-10-12 from Vietnam with our own client (`npm run probe -- <url>`): Node `fetch`, honest User-Agent `MaisonPrixBot/0.1 (non-commercial university project; +https://github.com/HvH1110/Web_Project)`, at least 5 s between requests per host. Re-run the probe before writing an adapter: sites change.

**Status values**
- `ready`: page loads for us, price is in the HTML, no adapter yet
- `active`: adapter written and in `npm run crawl`
- `no-price`: the source loads but shows no price
- `blocked`: the site refuses our crawler (bot protection). We don't work around it.
- `archive`: the live site blocks us, but the Internet Archive has its product pages: price **history** from Wayback snapshots (`npm run backfill`), no current price
- `todo`: candidate found, not verified yet
- `none`: no official or authorized online source found for this market

## Notes
- **Blocked sites.** Every blocked site answers our first request with a 403 from Akamai, so this isn't rate limiting. We don't spoof a browser User-Agent and don't run a browser to get past it. Louis Vuitton, Dior, Chanel and Van Cleef & Arpels sell only through their own boutiques, so no authorized dealer can stand in.
- **robots.txt is 403.** RFC 9309 would allow crawling when robots.txt returns 4xx. Our client still treats any non-404 failure as "disallow everything", because here the 403 is the bot wall itself.
- **Ref codes.** Per-brand formats are in `../docs/DATA.md` (Rolex `M124060-0001`, Cartier `L3002764`). Omega uses the dotted reference the official page shows: `210.30.42.20.03.001` (not `310-92-44-51-01-001` from Cortina's URLs or `21030422003001` from the official URLs).
- **Cartier.** The JSON-LD `price` is a display string (`S$ 580`, `HK$ 3,200`, `VND 11,400,000`), parsed into a number. A page without an `Offer` gives `price: null`. In scope: jewellery, watches, bags, small leather goods (not fragrances, eyewear, pens or home). About 4,600 product pages over three markets on one host is too many for a daily run, so each product is re-checked once every `CARTIER_ROTATION_DAYS` (default 7) days: about 660 pages, roughly 55 minutes, per run. A price change can therefore show up to a week late; `offers.lastSeenAt` says when each price was last checked. Some SG/HK `specs.Material` values come in French from Cartier's own data.
- **Daily run time** with the defaults (5 s between requests per host): exchange rates at most 5 minutes, DAFC about 18 minutes, The Hour Glass about 20 to 35 minutes (see below), Cartier about 55 minutes, Omega HK about 45 minutes: roughly 2 hours 20 to 40 minutes in all. Omega runs last, so a run cut short by the workflow timeout still updates the others.
- **Page errors.** A page that times out or answers 5xx is tried once more at the end of its source, 15 s apart. A source only counts as failed when it is blocked, has 10 errors in a row, or at least 5 and over 20% of its pages still fail; its saved pages stay either way.
- **The Hour Glass is unreliable by itself** (checked 2026-11-04): about a third of pages answered 500/502 after waiting 12 to 47 s, from GitHub and from a home connection alike, and different pages each time. Good pages can take 42 s, so this source gets a 90 s timeout. It was clean on 2026-10-21 (200 pages, 0 errors).
- **Exchange rates** (`fx_rates`, first step of `npm run crawl`). From Vietcombank's public rate table (`https://www.vietcombank.com.vn/api/exchangerates?date=YYYY-MM-DD`, robots.txt allows all, no login). It has every day from 2020-02-01, weekends and holidays included. We store its **sell** rate. ECB-based free APIs (Frankfurter) have no VND. Each run stores today plus up to 60 missing past days back to the oldest price point; older days are one request each, so a big gap fills over several runs (`npm run crawl -- fx --limit=N` to do more at once). Price points from January 2020 have no rate.
- **Manual prices** (`npm run import-prices`, see `manual/README.md`). For sites that block crawlers (Chanel, Van Cleef & Arpels, and current prices for Louis Vuitton, Dior, IWC), a person reads 10 to 20 signature products per brand from the official site in a normal browser and enters them in a CSV. The crawler itself still never fetches these sites, so they stay `blocked` or `archive` in the tables above. Source ids are the site's usual ones (`dior-sg`, `chanel-hk`), which no live source uses. If one of these sites ever gets a live adapter, its offers will replace the manual ones.
- **Wayback backfill** (`npm run backfill`). For brands whose live site blocks us, the Internet Archive has many archived product pages (tens of thousands each for LV SG/HK, thousands for Dior SG/HK, over a thousand each for IWC SG/HK, from 2020 on). They give price **history** only: products and `price_points` with `origin: wayback` and the snapshot link, never an offer, because an archived price is not today's price. We take only the price in the product's own markup (JSON-LD Offer, microdata), not analytics data. One snapshot per page per quarter (prices change a few times a year at most), newest first, about 500 per run (all on one host: web.archive.org). The capture index (CDX) is slow and often answers 503/504: it is asked one year at a time (one quarter at a time, 1,000 results per request instead of 5,000, when a year times out), history starts at 2020 (older pages are mostly products no longer sold), a busy answer gets one retry after a minute; if the index stays busy the run skips the rest of the index but still fetches what is queued, and stops if the snapshots answer busy too. Chanel SG (2019–2021) and Van Cleef & Arpels SG (2020–2021) also have archived pages; not checked for prices yet.
